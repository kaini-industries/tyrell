# CardputerZero installed baseline

Inspected November 13, 2026 over SSH using the existing project `.env`. One remote timestamp was `2026-11-13T17:24:02Z` (11:24 a.m. America/Chicago). These are observations of a running system; memory and service state are time-dependent.

This is the original pre-installation research baseline. The later addition and
test of `tyrell-status` is documented separately in
[device validation](device-validation.md); the firmware/launcher baseline was preserved.

The inspection used read-only commands. It did not elevate device privileges, install software, write configuration, scan I2C addresses, flash storage, update controller firmware, or restart services. Normal SSH authentication/audit activity may be recorded by the device. Credentials and Wi-Fi configuration are excluded from this report.

Do not derive the board-overlay selection solely from the raw hardware ID: the current working boot configuration selects v5 overlays despite the `0x06` value.

## Resource baseline

| Measurement | Observed |
| --- | --- |
| Linux-visible memory | 352 MiB; later sample 218 MiB used and 134 MiB available |
| Swap | Approximately 351 MiB reported; 91 MiB used |
| Block devices | `zram0` 352 MiB plus `loop0` 352 MiB swap device reported by `lsblk` |
| Physical card | `/dev/mmcblk0`, 29.1 GiB |
| Boot partition | `/dev/mmcblk0p1`, 512 MiB, FAT, mounted at `/boot/firmware` |
| Root partition | `/dev/mmcblk0p2`, 28.6 GiB, ext4, mounted `/` with `rw,noatime` |
| Root filesystem usage | Approximately 5.9 GiB used and 22 GiB available |

The official RAM specification is 512 MB. The installed `gpu_mem=128` setting reserves memory, and other kernel/firmware reservations also contribute to the smaller Linux-visible amount; this inspection did not account for every reserved page. Build and link applications on the host, VM or CI rather than on the handheld. [Hardware specifications](https://docs.m5stack.com/en/CardputerZero)

The original file additionally has conditional `[cm4]` and `[cm5]` USB sections, comments and blank lines. This excerpt is evidence, not a replacement configuration file.

Kernel command line uses an ext4 root selected by `PARTUUID`, `console=tty1`, `fsck.repair=yes`, `rootwait`, `quiet`, `fbcon=map:off`, and `cfg80211.ieee80211_regdom=AE`. Preserve or regenerate the correct image-specific root identifier. Make the deployment region configurable rather than inheriting `AE` by accident.

## Driver and peripheral evidence

- Keyboard: kernel input device `tca8418c`, I2C address `1-0034`, `/dev/input/event3` in this boot. Match by a stable device identity/udev link, not the event number.
- Display: `/dev/fb_lcd -> fb0`; `panel-mipi-dbid`, virtual size `320,170`, 16 bits per pixel. `/dev/dri/cardputer-zero-internal -> card1`.
- Loaded modules include `m5ioe1`, `tca8418_keypad_m5stack`, `es8389_m5stack`, `cardputerzero_audio`, `panel_mipi_dbi_m`, `pwm_bl_m5stack`, `gpio_forwarder`, `powerfail_suo`, `bq27xxx_battery_i2c`, `bmi270_i2c`, `bmc150_magn_bmi270`, `imx219`, `gpio_ir_recv`, and `gpio_ir_tx`.
- `/dev/i2c-*` and `/dev/spidev0.1` are present. No bus scan or direct register write was performed.
- Camera and IMU drivers/configuration are present, consistent with the full model's integration. Physical camera capture and sensor readings were not tested; installed drivers alone do not prove the populated variant.

`modinfo` was unavailable in the non-root shell PATH, so a module-specific `vermagic` value was not captured. Matching the running kernel and installed module presence is evidence, but the eventual build should explicitly verify module ABI metadata and load success.
